🤔 O que é um Model?

O Model é uma
classe Java que representa uma tabela
no banco de dados. Cada
atributo
da classe vira uma
coluna
na tabela. Cada
objeto
que criamos a partir dessa classe vira uma
linha

Analogia: Ficha de Cadastro

O Model é como uma
ficha de cadastro em branco
de fornecedor. A ficha define quais campos existem (nome, CNPJ, email...). Quando você preenche uma ficha, é como criar um objeto. Quando arquiva a ficha, é como salvar no banco! 🗂️

🗄️ O que é um Repository?

O Repository é uma
interface
(não uma classe!) que herda de
JpaRepository
. Ao estender ela, você ganha
de graça
vários métodos para operar no banco — sem escrever nenhum SQL!

Analogia: O Arquivista

O Repository é como um
arquivista super eficiente
. Você pede: "guarde esta ficha de fornecedor", "me dê o fornecedor de ID 3", "me dê todos os fornecedores". Ele faz tudo sem você precisar organizar o arquivo!

⚙️ O que é um Service?

O Service é a
camada de regras de negócio
. É aqui que a lógica acontece: validações, verificações, decisões. O Controller nunca acessa o Repository diretamente — sempre passa pelo Service.

Analogia: O Gerente da Loja

Imagine uma loja: o
atendente
(Controller) recebe o pedido do cliente. Mas quem decide se pode fazer a venda, se tem estoque, se o desconto é válido, é o
gerente
(Service). O gerente então manda o
estoquista
(Repository) buscar ou guardar os produtos.

🔍 O que é Optional e por que usamos?

▼

Optional<Fornecedor>
é como uma
caixa de presente que pode estar vazia ou ter um fornecedor dentro
.

Quando buscamos por ID, o fornecedor pode não existir. O Optional nos obriga a tratar esse caso:

.isEmpty()
→ a caixa está vazia? (fornecedor não existe)

.get()
→ pega o fornecedor de dentro da caixa

.isPresent()
→ tem algo na caixa?

Isso evita o famoso
NullPointerException
! 💀

🎮 O que é um Controller?

O Controller é a
porta de entrada
da API. Ele recebe as requisições HTTP (GET, POST, PUT, DELETE), chama o Service apropriado, e devolve a resposta. É aqui que definimos as
URLs
(endpoints) da API.

Analogia: O Recepcionista

O Controller é o
recepcionista
de um hotel. Ele recebe o hóspede (requisição), identifica o que ele precisa (método HTTP + URL), e encaminha para o departamento certo (Service). Quando o serviço é concluído, o recepcionista entrega a resposta.

🦋 O que é o Insomnia?

O Insomnia é uma
ferramenta para testar APIs
. Ele permite enviar requisições HTTP (GET, POST, PUT, DELETE) para o seu backend e ver a resposta — sem precisar de um frontend pronto. É como um
"controle remoto"
da sua API!

Analogia: Controle Remoto da TV

Imagine que sua API é uma TV. O frontend React é o controle remoto bonito que o usuário vai usar. Mas durante o desenvolvimento, você precisa de um
controle técnico
para testar todos os botões — esse é o Insomnia! Ele te permite apertar cada botão (endpoint) e ver se funciona, antes de construir o controle bonito. 📺🎮

🔗 Configurando a Base URL

Para não digitar
http://localhost:8080
em toda requisição, crie uma
variável de ambiente
:

1. Acessar Environment

Clique em
"Base Environment"
no painel esquerdo (ou no ícone de engrenagem ⚙️)

2. Adicionar variável

Adicione a variável
baseUrl
com o valor
http://localhost:8080

3. Usar nas requisições

Na URL de cada request, use
_.baseUrl
seguido do endpoint. Exemplo:
_.baseUrl/fornecedores

Se precisar mudar a URL base (ex: quando for pra produção), é só alterar em
um lugar só
— a variável de ambiente. Todos os requests atualizam automaticamente! 🎯
